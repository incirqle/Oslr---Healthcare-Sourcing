# Projects

Projects are the center of gravity in Oslr. Every search you run, every candidate you save, and every campaign you send (when Campaigns ships) lives inside a project. Most experienced Oslr users have between 5 and 30 active projects at a time.

---

## When to create a project

Create one project per role, search, or pipeline you're tracking. Common patterns:

- **One project per open role** — "Spine Surgeon — Mayo Rochester"
- **One project per geographic territory** — "DFW ICU Nursing Pipeline"
- **One project per recruiter or client** — common at agencies and PE platforms
- **One project per long-term pipeline** — "Family Medicine Residents Graduating 2027"

A candidate can live in multiple projects. Don't worry about overlap.

---

## Creating a project

1. Click **Projects** in the left nav.
2. Click **+ New Project** (top right).
3. Give it a name and an optional description.
4. Click **Create**.

You'll land on the empty project view, ready to source candidates.

---

## Adding candidates to a project

There are two paths:

### From inside the project — Source Candidates

Click **Source Candidates** at the top of the project view. The search hero opens, scoped to this project. Run your query, review results, and save the candidates that fit.

This is the path you'll use most often. It keeps the project context attached to the search, so when you switch back, the project knows which search produced which candidates.

### From the standalone Search screen

Click **Search** in the left nav. Run a query the same way. When you save a candidate, you'll be prompted to choose which project to save them to.

Use this when you're exploring a search that might feed multiple projects, or when you don't yet know which project a candidate belongs to.

---

## The project view

Once you have candidates in a project, you'll see them in a list. Each candidate row shows:

- **Avatar** with their initials.
- **Full name** with a LinkedIn icon if their profile is linked.
- **Current title** and **current employer**.
- **Location** (city, state).
- **Tag pills** showing matched specialty, location, and employer.
- **Email** and **phone** icons indicating whether contact info is on file.
- **Status** dropdown — defaults to "Unreviewed."

Click any row to open the candidate drawer with the full profile.

---

## Status — moving candidates through your pipeline

Every candidate in a project has a status. The default options are:

- **Unreviewed** — newly added; you haven't decided yet.
- **Reviewed** — you've looked at the profile.
- **Reaching out** — outreach in progress.
- **Replied** — they've responded.
- **Interested** — they've shown active interest.
- **Interviewing** — in your hiring process.
- **Hired** — closed-won.
- **Passed** — you decided not to pursue.
- **Not now** — good fit but timing's off.

Click the status dropdown on any candidate row to change it. Changes are logged.

You can rename or reorder status options for a project under project settings (when shipped — currently the defaults apply to all projects).

---

## Tags

Tags are flexible labels you can apply within a project. Use them for anything the default status doesn't cover:

- `j1-visa` for IMG candidates
- `passive` for not-actively-looking candidates
- `partnership-track` for candidates only interested in partnership opportunities
- `hot` for high-priority follow-ups

Tags are project-scoped — a candidate can have different tags in different projects.

---

## Sharing a project with teammates

If your workspace has multiple members, projects are shared by default with everyone in the workspace. To restrict a project to specific teammates, open project settings and adjust the **Sharing** panel.

Activity inside a shared project (status changes, notes, candidate adds, outreach) is logged with the teammate's name. You can see who did what at a glance.

---

## Tips

- **Name projects by the role, not the search query.** "Spine Surgeon — Mayo Rochester" is more useful six months later than "Mayo cards search v3."
- **Use status discipline.** A candidate stuck in "Unreviewed" for two weeks is signal you need to either review them or close the project.
- **Don't put a candidate in 8 projects.** If they're a fit for too many, you're not really tracking them. Pick the most relevant 1–2.
- **One project, one role.** Resist the urge to make a megaproject. Smaller projects are easier to act on.
